## Talks

### Go and Docker

Peter Preeper gave a hands-on introduction to packaging Go applications as Docker containers, starting with why Go is a good fit (statically compiled, single binary, garbage collection, CSP-style concurrency) and what containerization offers over VMs (smaller images, less configuration, reusable base images). He compared Dockerfile strategies: the convenience of `golang:onbuild` versus the control of `FROM golang:latest`, then showed how to shrink images dramatically with `FROM scratch`. The `scratch` approach required static linking (`CGO_ENABLED=0 GOOS=linux go build -a`) and hit a real-world snag — the HTTPS request to edmontongo.org failed because the image had no CA certificates, fixed by copying `ca-certificates.crt` into the container. The takeaway was to use `scratch` plus static linking to build tiny containers for microservices.

Key points:
- Go produces a single statically linked binary — ideal for containers.
- `golang:onbuild` is quick but bloated and gives little control.
- `golang:latest`/version images give build control but add many layers.
- `FROM scratch` yields the smallest images.
- Static linking (`CGO_ENABLED=0 GOOS=linux`) is required for `scratch`.
- Copy `ca-certificates.crt` for TLS/HTTPS to work in a `scratch` image.
- Use `scratch` + static linking for micro-containers/microservices.
