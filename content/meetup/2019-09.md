## Talks

### What's New in Go 1.13

Matthias Stone walked through the highlights of Go 1.13. TLS 1.3 is now on by default, cutting connection and reconnection overhead and dropping deprecated protocols. Number literals gained binary (`0b`) and octal (`0o`) prefixes, hexadecimal floating-point literals, imaginary suffixes, and underscore digit separators. The headline change for many was error wrapping: `fmt.Errorf`'s new `%w` verb wraps an error while preserving the chain, which `errors.Is`, `errors.As`, and `errors.Unwrap` can then inspect. The `go` command now downloads and authenticates modules through the module mirror and checksum database by default, and modules support was improved (active by default in `$GOPATH/src`, with sum verification).

Key points:
- TLS 1.3 enabled by default, with lower overhead.
- New number literal syntax: `0b`/`0o`, hex floats, imaginary literals, `_` separators.
- Error wrapping via `%w` in `fmt.Errorf`.
- `errors.Is`, `errors.As`, and `errors.Unwrap` inspect the wrapped chain.
- Module mirror and checksum database used by default.
- Improved module support in `$GOPATH/src`.

## Challengs

The evening's second half was a pizza-themed pair-programming challenge: write a Go program, using only the standard library, that works out how many pizzas to order from the number of people (`people/4`). Pairs were encouraged to have the less experienced gopher drive with the more experienced one mentoring. The challenge was staged: Phase I added validation and polish (`math.Round`, numeric-only input, correct pluralisation, and `go test` tests), Phase II introduced dietary restrictions (gluten-free, vegetarian, vegan) that had to be satisfied with least waste using table-driven tests, and Phase III wrapped the shared business logic in a web frontend built with `html/template` and `http.ListenAndServe`, with HTML5 input validation and `httptest` tests.

Key points:
- Build a pizza-count calculator with the Go standard library.
- Pairs: less experienced drives, more experienced mentors.
- Covered interactive, flag, and environment-variable input.
- Phase I: validation, pluralisation, and `testing` tests.
- Phase II: dietary restrictions, best-fit ordering, table-driven tests.
- Phase III: HTML frontend with shared business logic and `httptest`.

- We will be pair programming so experience with Go is optional
